# 资料服务接口

普通流分页由 $skip 决定；MultiDatastream 元数据的有序属性会随发布日期重排，其 definition 同步改变。单条观测的参数包含来源修订与解释引用，两个版本不等价。

观测身份使用 @iot.id，parameters.definition 是站点公开的解释版本引用。dataArray 的 components 决定行字段，结果数组内的位置与该流公布的 ObservedProperties 有序集合对应。/control 只推进本地站点的发布日期，不作为资料接口。

本地服务的资料入口为 `/observations/101`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。

## 按观测流领取

`POST /collections` 传入 `{"path": "<流>/Observations"}` 运行一次领取，普通流沿 `@iot.nextLink` 翻页，多维流按 `$resultFormat=dataArray` 取数并领取流元数据。同一流重复调用即为继续领取，采集结果按观测身份（@iot.id）持续合并，而不是把当前预览展开一次。

每条观测版本绑定领取当时的解释依据：普通流取观测 `parameters.definition` 指向的定义文档，多维流取该批元数据快照（有序属性与单位）加上其 `definition` 文档，两者顺序、单位须一致。读数据此注明采用了哪份属性、单位及传感器资料；站点更换传感器或结果定义后，旧版本仍按旧依据解释，新定义不会套到旧结果上。观测再次领取时若结果、解释版本或来源修订有变化，记为新版本并保留沿革，更正值由此进入采集结果并可继续追踪。

关联实体（定义文档、流元数据）领取失败时，已收原文仍留在原件目录并可凭摘要回读，但缺少解释依据的数值不进入可用观测集，在结果中标为暂时缺失并说明缺什么；继续领取会重试这些引用，资料到位后既有观测无需变更即可补齐。回读视图区分三种情形：没有任何观测（empty）、明确空值（explicitNull，结果为空）、暂时缺失（pending，数值被扣留）。
