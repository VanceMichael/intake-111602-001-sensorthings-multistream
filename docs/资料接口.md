# 资料服务接口

普通流分页由 $skip 决定；MultiDatastream 元数据的有序属性会随发布日期重排，其 definition 同步改变。单条观测的参数包含来源修订与解释引用，两个版本不等价。

观测身份使用 @iot.id，parameters.definition 是站点公开的解释版本引用。dataArray 的 components 决定行字段，结果数组内的位置与该流公布的 ObservedProperties 有序集合对应。/control 只推进本地站点的发布日期，不作为资料接口。

本地服务的资料入口为 `/observations/101`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。

## 按观测流领取

采集任务按流建立（普通流 `datastream-<id>`、多结果流 `multi-<id>`），状态保存在 `intake/`，重开目录后可继续领取。每次领取到的原文仍按摘要进入 `objects/`，关联实体领取失败只在任务的 `fetches` 留痕，不删除已收原文。

解释口径以观测自带的 `parameters.definition`（普通流）或流元数据 `properties.definition`（多结果流）为版本引用。每个引用对应一份独立上下文（定义文档、流快照），换版重排只新增快照，绝不修改旧版本：旧观测版本永久绑定领取当时的快照，新定义不会反套旧结果。

MultiDatastream 的列身份只由该版本快照的有序 `ObservedProperties` 决定，dataArray 的列序不具备属性身份；`components` 决定行字段名，解析不依赖固定位置。定义文档提供传感器资料，定义文档未领取时数值保留原文但不进入可用观测集，继续领取补齐后自动转可用。

三种缺失分别表达：

- 没有观测：流的分页全部为空数组，任务 `empty=true`，不计入观测数；
- 明确空值：站点给出的 `result: null`，是有解释依据的可用观测，`valueKind` 为 `null`；
- 暂时缺失：解释依据（流快照、定义文档、传感器）未领取，或行内结果列短于流属性数；观测留在 `pending` 并给出 `reasons`，补齐后转 `ready`。

同一 `@iot.id` 再次领取到不同结果或不同定义引用时追加为新版本，版本历史保留每份原文摘要与绑定定义；可用观测集只展示最新版本，更正次数为版本数减一。

`fixtures/intake.json` 保存采集场景的两个发布日期：首阶段定义文档未发布、一条流断连、部分行缺列；推进后发布更正值、两份定义文档并重排 MultiDatastream 属性次序。
